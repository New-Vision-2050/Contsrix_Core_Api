# دليل الفرونت إند — الإجازات الرسمية وكروت الفروع

آخر تحديث: 2026-09-22.

هذا الملف يصف الـ API المنفذة في الكود. يلزم نشر التعديلات وتشغيل الـ migrations الجديدة قبل استخدامها على السيرفر.

## 1. التغييرات المطلوبة

- استبدال `country_id` بحقل `branch_id` في الإضافة والتعديل والفلاتر.
- إدخال تاريخ البداية والنهاية بصيغة **`MM-DD`**: الشهر ثم اليوم، مثل `09-24` = 24 سبتمبر. لا تُرسل سنة في الإضافة أو التعديل.
- عرض `count_days` كما يرجع من الباك إند؛ العدد يشمل أيام التعويض ولا يُحسب في الفرونت من فرق التاريخين.
- تحميل كروت الفروع من endpoint جديدة، ثم تحميل الإجازات حسب الفرع والسنة المختارة.
- قراءة بيانات النجاح من `response.payload`.

## 2. إعداد الطلبات

```text
{{BASE_URL}}/api/v1/public-holidays
```

Headers:

```http
Authorization: Bearer {{ACCESS_TOKEN}}
X-Tenant: {{TENANT_ID}}
Accept: application/json
Content-Type: application/json
```

استخدم قيمة `X-Tenant` الخاصة بالشركة الحالية كما في بقية طلبات التطبيق. جميع العمليات تتطلب صلاحية الإجازات المناسبة للعملية.

## 3. كروت الفروع والسنوات

```http
GET /api/v1/public-holidays/branches
```

مثال استجابة:

```json
{
  "code": "SUCCESS_WITH_LIST_PAYLOAD_OBJECTS",
  "message": null,
  "payload": [
    {
      "branch_id": 12,
      "name": "فرع جدة",
      "years": [2025, 2026]
    },
    {
      "branch_id": 15,
      "name": "فرع الرياض",
      "years": []
    }
  ]
}
```

### ربط الاستجابة بالتصميم

1. كل عنصر في `payload` يمثل كارت فرع.
2. عنوان الكارت = `name`.
3. كل قيمة في `years` تمثل زر سنة.
4. عند الضغط على السنة، استدعِ القائمة باستخدام `branch_id` و`year`.
5. إذا كانت `years` فارغة، اعرض الكارت بحالة «لا توجد إجازات» مع إمكانية الإضافة بحسب صلاحية المستخدم.
6. بعد الإضافة أو التعديل أو الحذف، أعد تحميل الكروت والقائمة المعروضة لتحديث السنوات والبيانات.

الكروت تخص الشركة الحالية فقط، وتشمل الفروع التي لا توجد لها إجازات. السنوات مرتبة تصاعديًا وبدون تكرار، وتعكس السنوات المشمولة في فترات الإجازات المخزنة. لا تضف السنوات القادمة من عندك؛ تظهر بعد إنشاء سجلاتها.

لا تحتوي الاستجابة على صورة للفرع؛ استخدم الخلفية المشتركة الموجودة في تصميم الفرونت. علامة التنبيه الصفراء غير مطلوبة ولا يوجد لها حقل في الاستجابة.

## 4. إضافة إجازة

```http
POST /api/v1/public-holidays
```

```json
{
  "name": "إجازة رسمية",
  "branch_id": 12,
  "date_start": "09-24",
  "date_end": "09-26"
}
```

| الحقل | النوع | مطلوب | الوصف |
| --- | --- | --- | --- |
| `name` | string | نعم | اسم الإجازة، بحد أقصى 255 حرفًا |
| `branch_id` | integer | نعم | رقم فرع تابع للشركة الحالية؛ من نوع `branch` في `management_hierarchies` |
| `date_start` | string | نعم | شهر ويوم البداية بصيغة `MM-DD` |
| `date_end` | string | نعم | شهر ويوم النهاية بصيغة `MM-DD` |

استخدم رقم الفرع الراجع من API الكروت. لا تُرسل `country_id` أو `year` أو `count_days` أو `days` أو `is_recurring` ضمن نموذج الإضافة والتعديل.

### قواعد التواريخ والتكرار

- استخدم صفرًا قبل الشهر أو اليوم المكوّن من رقم واحد: `02-09` صحيح، و`2-9` غير صحيح.
- الإضافة تنشئ أول سجل في **السنة الحالية على السيرفر**، وليس بالضرورة السنة المفتوحة في الشاشة. بعد الإضافة استخدم `payload.year` لتحديد السنة التي تعرض نتائجها.
- البداية والنهاية متساويتان تعنيان إجازة يوم واحد.
- نهاية أسبق من البداية في ترتيب الشهر واليوم تعني امتداد الإجازة إلى السنة التالية: `12-31` إلى `01-02`.
- `02-29` مقبول؛ إذا كانت السنة الحالية غير كبيسة، يبدأ السجل في أول سنة لاحقة تصلح لها الفترة.
- الإجازة تتكرر سنويًا: الباك إند يولّد سجلات السنة الجديدة عبر أمر مجدول، بدون حاجة لاستدعاء من الفرونت.
- الإجازات المرتبطة بـ29 فبراير لا تُولّد في سنة لا تسمح بهذه التواريخ.
- احتفظ بقيم `MM-DD` كنصوص. لا تحولها عبر `new Date()` أو `toISOString()` حتى لا تتغير بسبب المنطقة الزمنية.

## 5. شكل بيانات الإجازة

الإضافة والتعديل والتفاصيل ترجع HTTP `200` وبداخل `payload` كائن إجازة. المثال التالي يفترض الإنشاء في سنة 2026؛ المعرفات توضيحية:

```json
{
  "code": "SUCCESS_WITH_SINGLE_PAYLOAD_OBJECT",
  "message": null,
  "payload": {
    "id": "6f20c14e-61d8-4d05-b8b9-7e3d24f0ca91",
    "name": "إجازة رسمية",
    "branch_id": 12,
    "date_start": "09-24",
    "date_end": "09-26",
    "year": 2026,
    "is_recurring": true,
    "count_days": 5,
    "days": [
      {"id": "8ed5e2bc-b7af-4f32-917b-2630c30d8181", "date": "2026-09-24", "is_compensation": false},
      {"id": "8ed5e2bc-b7af-4f32-917b-2630c30d8182", "date": "2026-09-25", "is_compensation": false},
      {"id": "8ed5e2bc-b7af-4f32-917b-2630c30d8183", "date": "2026-09-26", "is_compensation": false},
      {"id": "8ed5e2bc-b7af-4f32-917b-2630c30d8184", "date": "2026-09-27", "is_compensation": true},
      {"id": "8ed5e2bc-b7af-4f32-917b-2630c30d8185", "date": "2026-09-28", "is_compensation": true}
    ],
    "branch": {
      "id": 12,
      "name": "فرع جدة"
    }
  }
}
```

- `date_start` و`date_end`: الفترة المطلوبة، بصيغة `MM-DD`.
- `year`: سنة بداية السجل.
- `days`: الأيام الفعلية المطبقة، بتواريخ كاملة `YYYY-MM-DD`، وقد تختلف عن الفترة المطلوبة بسبب قواعد النقل والتعويض.
- `is_compensation`: هل اليوم تعويض عن عطلة أسبوعية.
- `count_days`: عدد عناصر `days`، شامل التعويض. في المثال: 3 أيام + يومين تعويض.
- بعض السجلات القديمة قد ترجع `branch_id: null` و`branch: null`؛ تعامل معها بدون خطأ في العرض.

## 6. قائمة الإجازات والفلاتر

إجازات الفرع عند الضغط على زر السنة:

```http
GET /api/v1/public-holidays?branch_id=12&year=2026&page=1&per_page=10
```

فلترة بشهر داخل السنة:

```http
GET /api/v1/public-holidays?branch_id=12&year=2026&month=9
```

فلترة بتاريخ بداية معين بالشهر واليوم:

```http
GET /api/v1/public-holidays?branch_id=12&year=2026&date_start=09-24
```

| Query parameter | الوصف |
| --- | --- |
| `branch_id` | رقم الفرع؛ أرسله عند عرض إجازات كارت معين |
| `year` | سنة بين 1900 و9999؛ الافتراضي السنة الحالية |
| `month` | رقم بين 1 و12؛ يتطلب إرسال `year` |
| `date_start` | مطابقة شهر ويوم البداية بصيغة `MM-DD` |
| `date_end` | مطابقة شهر ويوم النهاية بصيغة `MM-DD` |
| `search` | بحث جزئي في الاسم، بحد أقصى 255 حرفًا |
| `page` | رقم الصفحة، يبدأ من 1؛ الافتراضي 1 |
| `per_page` | حجم الصفحة من 1 إلى 100؛ الافتراضي 10 |

فلتر السنة والشهر يرجع الإجازات التي تتداخل فترتها مع الفترة المختارة، حتى لو بدأت في السنة أو الشهر السابق. الفلتر يعتمد على الفترة المطلوبة، وليس أيام التعويض التي قد تمتد إلى شهر لاحق.

قائمة فارغة ترجع `payload: []`. شكل مثال استجابة فارغة:

```json
{
  "code": "SUCCESS_WITH_LIST_PAYLOAD_OBJECTS",
  "message": null,
  "pagination": {
    "page": 1,
    "next_page": 1,
    "last_page": 1,
    "result_count": 0
  },
  "payload": []
}
```

عند وجود نتائج، كل عنصر في `payload` له نفس حقول كائن الإجازة في القسم السابق. استخدم `pagination` الراجعة للتنقل؛ قيم مثال الصفحة أعلاه توضيحية.

## 7. التفاصيل والتعديل والحذف

### التفاصيل

```http
GET /api/v1/public-holidays/{id}
```

ترجع كائن الإجازة داخل `payload`.

### التعديل

```http
PUT /api/v1/public-holidays/{id}
```

أرسل جميع حقول نموذج الإضافة الأربعة؛ لا تعتمد على إرسال الحقول المتغيرة فقط:

```json
{
  "name": "إجازة رسمية معدلة",
  "branch_id": 12,
  "date_start": "09-25",
  "date_end": "09-27"
}
```

التعديل يحتفظ بسنة بداية السجل الموجود. إذا كانت التواريخ لا تصلح لهذه السنة، مثل `02-29` في سنة غير كبيسة، يرجع خطأ تحقق.

**نطاق التكرار الحالي:** السجل الأصلي هو مصدر التوليد السنوي. تعديل نسخة مولّدة لسنة معينة يعدّل هذه النسخة؛ لا يغيّر تلقائيًا مصدر تكرار السنوات التالية. لا تعرض التعديل على أنه «تعديل كل السنوات».

### الحذف

```http
DELETE /api/v1/public-holidays/{id}
```

نجاح الحذف: HTTP `204` بدون بيانات؛ لا تحاول قراءة `payload` منه. احذف العنصر من الواجهة وأعد تحميل القائمة والكروت.

الحذف يستهدف السجل المحدد. حذف السجل الأصلي يوقف التوليد اللاحق منه، والنسخ التي تم توليدها بالفعل تبقى موجودة.

## 8. التصدير

```http
POST /api/v1/public-holidays/export
```

```json
{
  "format": "xlsx",
  "branch_id": 12,
  "date_start": "2026-01-01",
  "date_end": "2026-12-31"
}
```

الاستجابة ملف للتنزيل، وليست JSON؛ استخدم `responseType: "blob"` أو المقابل في مكتبة الطلبات.

| الحقل | الوصف |
| --- | --- |
| `format` | `xlsx` أو `csv`؛ الافتراضي `xlsx` |
| `branch_id` | رقم الفرع |
| `name` | بحث جزئي بالاسم |
| `date_start` | حد أدنى لبداية الإجازة بصيغة **`YYYY-MM-DD`** |
| `date_end` | حد أقصى لنهاية الإجازة بصيغة **`YYYY-MM-DD`** |
| `ids` | مصفوفة معرفات UUID للإجازات المراد تصديرها |

حقول التصدير اختيارية. **التصدير الحالي يستخدم تاريخًا كاملاً**، بخلاف الإضافة والتعديل وفلاتر تاريخ القائمة. لا ترسل له `year` و`month` وتفترض أنه سيطبّق فلترهما؛ استخدم حدود التواريخ أو `ids`.

## 9. أخطاء التحقق

مثال HTTP `422`:

```json
{
  "success": false,
  "message": "تعذر التحقق من البيانات",
  "errors": {
    "date_start": ["يجب أن يكون التاريخ شهرًا ويومًا صالحين بصيغة MM-DD."]
  }
}
```

نص `message` يتغير حسب لغة التطبيق. اربط `errors` بالحقول المقابلة ولا تعتمد على نص رسالة ثابت.

حالات ينبغي التعامل معها:

- فرع غير موجود، أو ليس فرعًا، أو غير تابع للشركة الحالية.
- تاريخ غير صالح مثل `04-31` أو بصيغة كاملة مثل `2026-09-24` في الإضافة.
- إرسال `month` بدون `year` في القائمة.
- غياب حقول مطلوبة أو تجاوز حدود الترقيم.
- HTTP `401` عند غياب تسجيل الدخول، وأخطاء الصلاحيات وفق معالج الأخطاء الحالي للتطبيق.

## 10. ملاحظات التسليم

- الأمر السنوي مجدول يوم 1 يناير الساعة 00:01 بتوقيت الرياض. تشغيله على السيرفر يعتمد على تفعيل Laravel Scheduler.
- لا تحتاج الواجهة لاستدعاء endpoint لتوليد السنة أو إنشاء نسخ مكررة.
- طبّق الشاشات على البيانات الراجعة؛ صور الكروت وعلامة التنبيه ليستا ضمن عقد الـ API الحالي.
- يلزم تنسيق نشر الباك إند والـ migrations قبل نشر تحديث الفرونت الذي يعتمد على `branch_id` و`MM-DD`.
